I would freeze the architecture now and stop extending the current monolithic AJInstitutional.js. The current OpenAlgo implementation is useful as a deployment proof, but it is the wrong long-term architecture for reproducing the original AJIndicator.

The original AJ code already demonstrates the architecture we want: RuntimeEngine → AJRuntimeContextBuilder → AJPayloadBuilder → AJDecisionEngine → AJRuntimeEngine/RuntimeResult, with the decision engine coordinating Context, AI, SMC, Authority, State Machine and Execution rather than putting everything into one indicator file.
